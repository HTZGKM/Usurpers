# 顾客端设计工作流：The Hearth

## 核心原则

**类魂游戏史诗风格是首要设计理念。** 主管页提供品牌与氛围基准；Qitchen 是摄影构图、排版和交互完成度的参考。顾客页不固定沿用主管色板：幽暗石厅、炉火、旧黄铜、亚麻与共享餐桌负责传达史诗感，界面以纯黑、暖白和少量浅金保持清晰、克制。

概念：Double Portion 的「共享一餐」成为烛火石厅里的一次邀约。首页大图建立场所感，三张不同的照片分别把人带向菜单、座位与厨房故事。保留既有英文产品文案、14 道菜、价格、账户和演示业务流程。

## 每轮执行

1. **核对基准**：先读 admin.css、顾客交接、当前模板和 JS，记录现有截图，确认角色边界与行为钩子。
2. **参考拆解**：对照 Qitchen 首页 / menu / reservation，分别检查主次比例、照片裁切、字体层级、页边距、悬浮导航、内容滚动和窄屏行为；不导入模板商业素材。
3. **视觉定稿**：顾客页采用下方独立色板；首页约 74/26，内页约 50/50。Palatino 系统衬线承担标题，系统无衬线承担信息与表单。以图片建立史诗感，导航、菜单和表单保持适度字级，避免大面积金色或绿棕色面板。
4. **素材制作**：分开生成场所、餐食、餐桌与炉火四类画面。相同光线、材质和色温；检查主体与文字区；保留来源记录，导出本地 WebP。既有菜单图继续准确对应菜名。
5. **实现**：优先共用 cover / homepage 宏；顾客样式仅在非 staff 页面加载。保留 data-action、模板 ID、表单字段、CSRF、图片基础目录与现有路由。
6. **浏览器验收**：桌面 1440、平板 768、手机 390；检查图像加载、文本溢出、菜单吸顶、弹层、键盘焦点、导航 Esc、表单和减少动画偏好。
7. **业务回归**：匿名访问与登录引导 → 顾客登录 → 订座与选桌 → 菜品配置与购物袋 → 演示下单付款。主管角色样式隔离。测试使用独立数据库或既有种子账号，不创造真实交易。
8. **复看与交付**：截图检查至少一轮并修正最明显的问题，记录实际测试结果与遗留边界；保留本地预览。未经请求不提交或推送。

## 业务边界

本轮属于前端视觉优化。认证仍使用 Flask/SQLite；顾客订座、签到、购物袋、下单和付款沿用 sessionStorage 演示流程。保留后端接口、数据库内容、权限判断、表单字段和业务事件；顾客专属 CSS 不加载到员工工作台。Delivery 继续明确标注 Coming soon。新生成图片用于概念场景，正式上线前应替换或确认其与真实场所和菜品的一致性。

### 2026-11-23 录屏动效校准

逐帧分析用户提供的 56.58 秒 Qitchen 录屏：约 30.5 秒 Menu → Reservation、39.1 秒 Reservation → About、43.1 秒 About → Home。画面先短暂叠化，标题随后以逐字透明度与模糊变化出现，单词与行之间顺序衔接；导航保持稳定。菜单左侧封面固定，右侧清单滚动。首页中的手和筷子持续运动，属于实际视频内容，不能用静态照片缩放等同替代。

应用到顾客端的参数：背景照片叠化 280ms；标题每字 480ms，从 7px 模糊到清晰，首字延迟 180ms，字间隔最多 60ms、总错峰不超过 400ms；正文淡入 440ms，首页入口依次淡入。保留标题原有字重、换行与可访问名称。沿用石厅、烛光、餐食与炉火的类魂氛围，本轮没有新增首页视频素材。

叠化只保留一个短暂的装饰性旧照片副本，不复制导航或业务表单；页面挂载及业务更新继续同步执行。连续切换立即清理上一张副本，动画结束、取消、减少动画偏好变化均清理副本。减少动画模式直接呈现最终画面。顾客动效脚本不加载到员工工作台。

验收：8 项照片副本生命周期与同步更新测试、6 项页面资源及角色隔离测试通过；JavaScript 语法检查和 `git diff --check` 通过。内置浏览器复测桌面快速 Menu → Booking → Your visit 后逐级返回、手机 Home/Booking 连续切换、菜品数量即时更新与弹窗关闭。1440px 桌面与 390px 手机截图复看，320px 的账户、Journal、Delivery、Menu 无横向溢出；控制台无警告或错误。录制当前页面真实切换并保存为独立 GIF，录屏、抽帧与验收素材均不进入 Git。减少动画清理行为有单元测试，CSS 已静态复核，未切换操作系统偏好做浏览器动态实测。
