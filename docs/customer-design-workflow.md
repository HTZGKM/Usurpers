# 顾客端设计工作流：The Hearth

## 核心原则

**类魂游戏史诗风格是本轮的首要设计理念。** 主管页是品牌系统的基准；Qitchen 是摄影构图、排版和交互完成度的参考。用幽暗石厅、炉火、旧黄铜、亚麻与共享餐桌构成温暖的避风处，让氛围庄严、食物诱人、操作清楚。

概念：Double Portion 的「共享一餐」成为烛火石厅里的一次邀约。首页大图建立场所感，三张不同的照片分别把人带向菜单、座位与厨房故事。保留既有英文产品文案、14 道菜、价格、账户和演示业务流程。

## 每轮执行

1. **核对基准**：先读 admin.css、顾客交接、当前模板和 JS，记录现有截图，确认角色边界与行为钩子。
2. **参考拆解**：对照 Qitchen 首页 / menu / reservation，分别检查主次比例、照片裁切、字体层级、页边距、悬浮导航、内容滚动和窄屏行为；不导入模板商业素材。
3. **视觉定稿**：主管色板固定；首页约 74/26，内页约 50/50。Palatino 系统衬线承担标题，系统无衬线承担信息与表单。大图和字级承担史诗感。
4. **素材制作**：分开生成场所、餐食、餐桌与炉火四类画面。相同光线、材质和色温；检查主体与文字区；保留来源记录，导出本地 WebP。既有菜单图继续准确对应菜名。
5. **实现**：优先共用 cover / homepage 宏；顾客样式仅在非 staff 页面加载。保留 data-action、模板 ID、表单字段、CSRF、图片基础目录与现有路由。
6. **浏览器验收**：桌面 1440、平板 768、手机 390；检查图像加载、文本溢出、菜单吸顶、弹层、键盘焦点、导航 Esc、表单和减少动画偏好。
7. **业务回归**：匿名访问与登录引导 → 顾客登录 → 订座与选桌 → 菜品配置与购物袋 → 演示下单付款。主管角色样式隔离。测试使用独立数据库或既有种子账号，不创造真实交易。
8. **复看与交付**：截图检查至少一轮并修正最明显的问题，记录实际测试结果与遗留边界；保留本地预览。未经请求不提交或推送。

## 固定设计规范

| 角色 | 值 / 规则 |
| --- | --- |
| 底色 | #0d0e0c |
| 面板 | #191916 |
| 正文 | #ede8d8 |
| 次级文字 | #b6b0a1 |
| 旧金强调 | #e2c898 |
| 边线 | #37362e |
| 标题 | Palatino Linotype / Palatino / Book Antiqua / Georgia |
| 操作文字 | Segoe UI / system-ui |
| 页面边距 | 桌面 16px，手机 10px |
| 图片框 | 10px 圆角，保持 Qitchen 的画框感 |
| 动效 | 短距离淡入，缓慢照片收拢，悬停微缩放；尊重 prefers-reduced-motion |
| 图片 | 自托管 WebP；装饰性图像空 alt，内容性图像描述画面 |

主管的细线与菱形识别保留，照片暗角只用于文字可读性。避免武器、角色立绘、发光粒子、夸张仿古边框和难读的黑字黑底。

## 参考与取舍

- [Qitchen 官方预览](https://qitchen-template.framer.website/)，并核对 menu 与 reservation。
- [项目原有 Qitchen Figma 参考](https://www.figma.com/design/k70rXmeKFMpb20H0Odvvof/)。本轮实际视觉对照使用官方在线预览。
- [Qitchen 官方模板说明](https://www.framer.com/marketplace/templates/qitchen/)。免费模板不等于素材全部开源，本轮使用新生成的场景图。
- design-taste-frontend 抽取方向：**The place carries it**，seed **81484400**。保留用户已有品牌颜色和字体。首页采用大图与窄入口列；为保留现有应用流程与明确 Qitchen 参考，不引入抽样建议的多屏滚动场景和色块导航。
- ui-ux-pro-max 的自动匹配给出 Liquid Glass 与通用展示页，和本轮史诗餐厅方向不符；仅采用其对比度、焦点、触控、响应式与减少动画检查规则。

## 业务边界

本轮属于前端视觉优化。认证仍使用 Flask/SQLite；顾客订座、签到、购物袋、下单和付款沿用 sessionStorage 演示流程。Delivery 继续明确标注 Coming soon。新生成图片用于概念场景，正式上线前应替换或确认其与真实场所和菜品的一致性。
